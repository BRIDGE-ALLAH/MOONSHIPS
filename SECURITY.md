# MOONSHIPS Security Policy

## Reporting a vulnerability

**Do not open a public issue for a suspected security vulnerability.**

Use [GitHub's private vulnerability reporting for MOONSHIPS](https://github.com/BRIDGE-ALLAH/MW/security/advisories/new). Include the affected commit or release, affected component, impact, reproduction steps, and a proof of concept when safe to provide.

If private vulnerability reporting is unavailable, contact the repository maintainers through the contact information published in the MOONSHIPS repository profile. Do not send secrets, customer data, or production credentials.

## Scope

The project scope includes the MOONSHIPS core panel and API, compatible agent/helper components, installer and updater scripts, and the default configuration produced by this repository. Existing Pier-named binary, service, filesystem, and environment identifiers are compatibility interfaces, not the public product name.

Third-party dependencies and software deployed by MOONSHIPS should be reported to their respective maintainers unless the vulnerability is caused by a MOONSHIPS-specific integration or unsafe default.

## Handling

Maintainers will acknowledge reports, assess reproducibility and impact, coordinate a fix, and publish an advisory when appropriate. Do not assume a fixed response deadline; updates will be provided through the private report.

Please allow maintainers a reasonable opportunity to investigate and prepare a fix before public disclosure. Coordinated disclosure does not prevent reporters from following applicable law or platform policies.

## Credit

Reporters may request attribution or anonymity when a fix or advisory is published. MOONSHIPS does not currently advertise a paid bug bounty.
